- 在中国大陆的电脑上规划，在日本的手机上查看；同一个人跨设备使用。
- 先试用 CloudBase，优先免费体验，不先购买服务器或付费套餐。
- 网页继续使用 GitHub Pages；云端保存个人修改，本地保留缓存。
- 已有浏览器数据首次同步前需要备份，不能被云端空数据覆盖。

最新选择：用户决定改试 Supabase Free。官方 SDK 本地分发，SQL 使用 UUID 用户 ID，保留同步状态提示、首次选择、备份和数据库原子版本检查。CloudBase 方案归档，不再作为当前网页后端。

Supabase 项目 `https://lwxrifdcrhaizcobrpfp.supabase.co` 已配置发布；所有者确认 SQL 和个人应用账号已创建。从真实 GitHub Pages 来源验证，匿名 RPC 返回预期 `42501`，未遇到跨域拦截。103 项本地测试及桌面/手机浏览器备份流程通过；账号写入和跨设备读取待所有者实际验证，不能用匿名拒绝代替该结果。

历史选择：腾讯云 CloudBase 的托管账号认证和数据库，原因是无需维护服务器，适合先验证大陆编辑和日本查看的工作流。

已由用户创建环境 `jpmap-d2gsyqixu8b7f8714`，地域上海、PostgreSQL 模式。已准备浏览器登录/同步代码、SQL 权限配置及本地验证；尚需所有者执行云端 SQL、创建应用账号并配置域名，才能验证完整同步。没有实测日本网络。

后续验证发现阻塞：用户控制台添加跨域来源需升级套餐；真实 GitHub Pages 来源的数据库 RPC 预检被 CORS 拦截。当前 CloudBase 免费环境不能按现有架构完成线上同步，原免费可用的选型假设未成立。付费或替代服务尚待选择，不能继续宣称仅剩配置即可免费同步。

## 接入前置条件

由所有者登录腾讯云并完成控制台要求的账号验证、服务开通及免费环境创建。收集环境 ID、地域、数据库模式；费用和试用到期时间以创建页面为准。

CloudBase 同时存在传统模式和 PostgreSQL 模式，数据库 API、认证与权限配置须匹配实际环境，不能混用教程。先确认模式，再选择对应 SDK 版本和登录方式。

## 同步约定

- 使用同一个个人账号；每份行程有所有者、版本及更新时间。
- 地点、日期、住宿信息、航班个人备注、关注作品参与同步；不上传定位轨迹或天气缓存。
- 先保存本地，再上传；明确显示待同步、已同步及失败状态。
- 首次导入由用户选择，不以默认模板或空记录覆盖已有行程。
- 云端写入必须检查版本，避免手机旧数据覆盖电脑新数据；不能只用客户端时间判断先后。
- 所有者权限必须在后端执行。前端登录界面和来源域名白名单不能代替数据权限。
- 管理员 SecretId、SecretKey、私钥及账号密码不写入代码或 GitHub。
- 登录后私有数据与当前公开代码中的默认行程是两回事；接入账号不会撤回既有公开历史。

## 后续验证

真实环境下验证：登录、电脑保存、手机读取、刷新后恢复、权限拒绝、离线失败与重试、版本冲突、首次导入和备份恢复。模拟测试不能证明云端链路可用。
