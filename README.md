# 日本旅行地图

## 在线访问与 GitHub Pages

在线地址：https://xzqxh.github.io/JPmap/

仓库：https://github.com/XZQxh/JPmap

GitHub Pages 使用 `main` 分支根目录发布，推送到 `main` 后自动更新。根目录的 `.nojekyll` 让 GitHub 直接发布静态文件，无需安装依赖或运行本地服务器。更新前可运行 `node --test tests/*.test.cjs` 检查功能。本地还可运行 `node scripts/build-pages.cjs` 打包仅包含网页资源的版本到 `_site/`（不提交到仓库）；当前 Pages 直接发布仓库根目录，测试代码及预览截图也可公开访问，`server.js` 不会在 GitHub 上运行。

此仓库和网站公开，按所有者要求保留现有旅行日期、住宿地址和预订链接。浏览器里后续编辑的行程仅保存于当前设备与网址，不会自动提交 GitHub，也不会从本地网址自动迁移到在线网址。HTTPS 可用于手机定位，仍需设备授权。地图、机厅、巡礼和天气依赖各自的第三方服务及其跨域访问规则。

## 本地运行

双击 `start.cmd`，保持窗口打开，在浏览器访问 http://127.0.0.1:8765 。需要 Node.js，无需安装依赖。

手机调试：服务默认监听 `0.0.0.0:8765`，启动窗口会打印本机的局域网访问链接。手机与电脑连接同一个局域网，在手机浏览器打开对应的 `http://电脑局域网IP:8765`，并保持电脑服务运行。修改监听后需要重启旧服务。若 Windows 弹出防火墙提示，允许 Node.js 在当前专用网络中访问；访客 Wi-Fi 或设备隔离可能阻止互访。需要限制为仅电脑访问时，可设置环境变量 `JPMAP_HOST=127.0.0.1`。

手机宽度下采用单屏地图布局，地图占据顶部工具栏以外的主要空间。底部行程有收起、半屏、全屏三档：拖动灰色横线或整条摘要栏即可连续调整，松手后吸附到合适高度；上拉看完整行程，下拉回到地图。也可点击摘要栏依次展开、全屏、收起，或在把手上用键盘上下方向键、Home/End 切换。全屏内可选择行程日期，列表本身仍可滚动，不会把滚动误当作拖动。附近查询会展开结果面板，已处于全屏时保持全屏。定位保留为图标按钮，机厅/圣地的当前位置与地图中心查询收进“附近查找”，底图与轨道开关收进地图右上角的设置按钮。页面本身不再上下滚动挤压地图。电脑端仍为地图与行程并排布局。

局域网 HTTP 适合检查手机布局、地图拖动、按地图中心找机厅等功能；手机的实时定位和“当前位置”查询通常需要 HTTPS。手机行程保存在手机浏览器中，不会自动同步电脑上的编辑。

默认地图使用 MapLibre GL JS 与 [OpenFreeMap](https://openfreemap.org/quick_start/) 的 Bright 彩色样式，调整为蓝色水面、绿色公园、黄橙色道路、淡色平面建筑及按类别配色的地点标签。铁路为绿色、地铁等城市轨道为紫色、车站为蓝色；这些颜色仅作类型区分，不对应运营商的线路颜色。车站和商铺名称随缩放与数据覆盖显示；可用“轨道与车站”开关控制轨道和车站。它不提供实时班次或换乘规划。

底图菜单可切换“彩色旅行地图”“淡色简洁地图”（原 Positron 定制样式）和国土地理院备用底图。当前彩色地图的数据仍来自 OpenStreetMap，并非 Microsoft / Zenrin，商铺名称、覆盖密度与 nearcade 截图会有所不同。Microsoft 官方地图服务需自有账户和鉴权配置，不能靠复制署名接入其数据。新样式由 `scripts/prepare-color-style.cjs` 从 OpenFreeMap 官方 Bright JSON 生成，保存在 `map-color-style.js`，无需用户申请地图 Key。

航班卡片包含机场接驳的 Google 地图公交路线链接，保留航站楼；地点卡片、地图弹窗和编辑窗口统一只保留“在 Google 地图查看”，打开地点信息，不直接进入导航。Google 会按设备打开 App 或网页版。请在机场接驳路线中选择实际出发时间，链接不会自动锁定 2027 年旅行日期。已填写地址的地点优先使用完整地址，没有地址时使用坐标。

大阪、东京住宿已根据用户提供的信息填写为 Airbnb，京都为携程预订。住宿卡片显示完整地址，提供一个 Google 地点查看入口和预订平台链接；Google 地图、Airbnb、携程按钮带对应应用图标，图标存放在本地 assets 目录。两条 Airbnb 行程链接按用户提供顺序分别对应大阪、东京，打开可能需要登录；京都跳转携程首页。地址与个人行程链接仅在本地原型中保存，未打开或检查私人订单。

大阪住宿采用用户提供的坐标：34°39′22.2″N 135°29′37.1″E，即 34.6561666667, 135.4936388889；图钉、Google 地点查看和机场接驳使用同一坐标。东京、京都图钉仍为区域示意，Google 地图优先使用完整地址。首次打开新版会自动修正已保存的大阪图钉，保留日期、排列顺序、预订链接和个人备注，不恢复已删除地点。京都地址参考 https://www.hearton.co.jp/access/kyoto 。

地图服务与导航链接均不需要 API Key。地图和 Google 地图需要网络；矢量地图加载失败时，可以重试或切换“淡色备用地图”（国土地理院）。备用栅格地图无法单独隐藏轨道与车站，因此该模式禁用开关。MapLibre 需要支持 WebGL 的浏览器。

推荐通过 `start.cmd` 启动；也可直接打开 `index.html`，但浏览器对本地文件和跨域资源的限制可能影响地图显示。请保留同目录的 `map-color-style.js` 和 `map-style.js`，分别为彩色及淡色地图的样式配置。来源和署名见 [THIRD_PARTY.md](THIRD_PARTY.md)。

行程保存在当前浏览器和网址下。直接打开文件与本地 HTTP 地址的存储相互独立；更换打开方式不会自动迁移原行程。保持使用同一个地址即可继续编辑。

## 搜索地址并添加地点

地图右上角“＋ 添加”和行程底部“＋ 添加地点或备注”均直接打开添加窗口。输入至少两个字的景点名称或地址，停止输入约 0.9 秒后自动搜索，也可点“搜索地址”或在名称框按 Enter 立即搜索。支持中文、日文和英文检索，找不到时可尝试日文原名或加上城市名称。

搜索通过 [Photon](https://photon.komoot.io/) 公开接口查询日本境内的 OpenStreetMap 地点，每次最多显示六个候选，以当前主地图中心作为参考位置，不请求设备定位。候选名称、地址和坐标与窗口内小地图的编号对应；点击列表或地图编号后回填名称、地址及坐标，再按“保存地点”才会加入所选日期。完整地址栏附带地点名称，便于在 Google 地图中查看。搜索本身不会修改或保存行程。

来源地址可能只有街道或区域，没有门牌号时明确提示可补充，不保证与 Google 地图覆盖一致。断网、超时、服务限流、没有结果均会提示；候选地图加载失败时仍可用列表选择。也保留直接点击主地图放置地点、手动填写地址的方式。输入中的中文/日文组合文本不会触发搜索；修改名称、切换查询或关闭窗口会取消旧请求，避免迟到结果覆盖当前选择。

名称及主地图中心的参考坐标（保留两位小数）在搜索时发送到 Photon，不发送行程、备注或预订链接。相同查询在当前页面缓存 30 分钟，搜索请求至少间隔一秒；公共服务可能限流，不保证可用性。新增 `place-search.js` 与 `place-search-ui.js` 已加入本地服务与静态打包清单，运行旧本地服务时需重启。GitHub Pages 可直接运行，无需后端或 API Key。

## 找机厅与当前位置

- “mai一下 / 找当前位置机厅”在点击时获取一次位置，将该坐标发送到 nearcade 的公开 `/api/discover` 接口；固定 `radius=5`、`gameTitleIds=1`（maimai DX），沿用其返回顺序与覆盖范围，不进行本地 5 km 截断或重新排序。来源的 5 km 档包含出行预算，因此结果可能超过直线 5 km。每次最多展示来源返回的 150 家。
- “找机厅 / 按地图中心”不请求手机定位，明确使用当前地图中心作为查询点。两个查找按钮使用相同的 maimai 图标并归为一组，清楚区分查找起点。图标也用于机厅标记、类别筛选、结果标题和加入计划入口；源文件由用户提供，保存在 `assets/maimai.ico`。
- 地图中心查找适合出发前规划，也可在拒绝定位时使用。地图与列表提供机台原始备注、Google 导航、nearcade 来源和加入当天计划。收起面板可取消未完成请求并回到行程地图。
- “显示我的位置”是独立开关，使用 `watchPosition` 更新蓝点与定位精度圈。只在第一次获得位置时居中，后续移动更新蓝点而不抢占地图视角。定位失败时提示状态，最后位置蓝点变淡；关闭开关或离开页面即停止监听。不会保存位置轨迹，不会随位置更新自动请求 nearcade。
- 手机浏览器需要 HTTPS、系统定位服务和浏览器定位授权。电脑 `localhost` 可用于调试；手机直接打开局域网 HTTP 地址通常无法定位。页面在前台时按设备提供的定位频率更新；锁屏和后台更新可能被浏览器暂停，不能代替专用导航 App。
- nearcade 返回的机厅数据会更新，机台数量等备注以来源为准。当前原型直连其公开 API；生产部署还需验证部署域名是否被其 CORS 规则允许。

运行检查：`node --test tests/*.test.cjs`。位置测试使用模拟坐标，不获取真实位置。

## 行程天气与富士见预报

日期按钮下面显示当地城市与天气摘要；行程面板内显示当天的天气、最低/最高气温、最大降水概率和最大风速。默认对应大阪、京都、东京；2/17 转场日同时显示京都、大阪、东京。加入行程的远郊地点如果距离现有预报点至少 20 km，会单独查询其坐标的天气，市内地点共用城市预报。未排期不显示天气。

天气直连 [Open-Meteo Forecast API](https://open-meteo.com/en/docs)，无需 Key，统一使用日本时间，查询未来 16 个自然日（含今天）。超出范围显示“待预报”和预计可查询日期，不使用当前天气、历史均值或虚构天气替代。2027/2/12 最早预计 1/28 进入范围，富士见候选首日 2/18 最早预计 2/3 进入范围；实际字段覆盖以接口返回为准。远期预报标为“远期趋势”，临近再确认。

东京段单独显示富士见面板，默认看河口湖方向，可切换山中湖、箱根芦之湖。并排比较 2/18–2/21，点击候选日切换对应行程；2/17 转场及 2/22 返程不参与推荐。以观景点 07:00–17:00 内有日照的连续三小时数据计算参考分，并显示较好窗口、平均总云量/低云量、最低能见度、最大降水概率。少云占 45 分、地面能见度占 30 分（30 km 封顶）、低降水概率占 25 分；雨雪量 ≥ 0.2 mm、降水概率 ≥ 60% 或能见度 < 10 km 限制到 39 分以下。“较适合”还需总云 ≤ 40%、低云 ≤ 30%、能见度 ≥ 20 km、降水概率 ≤ 20%。缺少连续数据或已过时段不会评分。

富士见分数是自定义的相对参考分，不是见山概率或官方富士山可见度预报；没有完整模拟山顶、整段视线的云雾及地形遮挡。建议出发前 1–3 天结合现场情况复核，不因东京晴朗就认定富士山可见。

天气按坐标合并请求，当前页面内缓存 30 分钟，页面前台每 30 分钟更新；恢复前台时检查缓存和日本日期。支持手动刷新、15 秒超时、失败重试；保留的旧数据带标记，旧数据和失败数据不参与富士见推荐。数据和个人行程分开保存，天气查询不会修改原行程。天气需要网络；直接打开文件的跨域访问取决于浏览器，建议使用本地服务。新增了 `weather.js`、`weather-ui.js`、`weather.css` 的服务白名单，升级后需要重启旧 `server.js` 服务。

## 找找圣地（关注作品）

“找找圣地”有“当前位置”和“地图中心”两个入口，搜索直线距离 **2 km** 内的关注作品点位。前者在点击后请求一次定位，后者直接使用地图中心，不请求设备定位。距离在本机计算，Anitabi 只接收作品 ID，不接收查询位置。两个来源的结果面板互斥，关闭面板或切换到找机厅会取消未完成的巡礼查询。

默认关注吹响吧！上低音号（115908）、轻音少女（1424）、MyGO（428735）、孤独摇滚（328609）。在结果面板的“管理关注作品”中可以勾选、移除或添加最多 20 部作品；接受数字 ID、完整 Bangumi 作品链接或 Anitabi 作品地图链接。续作、剧场版、其他 BanG Dream! 动画需单独添加，不会自动扩展整个系列。关注列表保存在本机浏览器中。

按 [Anitabi 开放 API 文档](https://github.com/anitabi/anitabi.cn-document/blob/main/api.md)，读取 `/bangumi/{id}/points/detail` 的点位及 `/bangumi/{id}/lite` 的作品名称与主色。不会使用只有前十个地标的 `litePoints` 代替完整点位，也不会请求主站静态数据或未文档化的全站索引。作品颜色用于地图图钉、结果卡和图例；颜色缺失时使用固定备用色。支持按作品筛选、Google 导航、Anitabi 来源、加入当天计划或未排期；加入计划后保留作品颜色、名称、点位 ID 和来源。

查询最多同时加载两部作品，每个请求 15 秒超时，成功结果在当前页面内缓存一小时；“刷新来源数据并重查”清缓存后重新读取。列表分批显示 30 个点位，缩略图按需加载，保留原始资料/截图出处和协议署名。部分作品失败、返回数量少于作品报告总数或坐标缺失时均明确标注，失败不会显示成“附近没有圣地”。API 仍可能没有返回全部资料，本功能不宣称覆盖全站所有圣地。

当前环境对 Anitabi 官方示例接口的实际探测返回 HTTP 403，因此真实点位的在线成功链路暂未验证。需要在实际使用网络/部署域名下确认官方 API 的访问及 CORS；不会通过抓取主站或绕过访问限制替代。距离边界、坐标顺序、颜色、部分失败、取消、缓存等逻辑使用合成测试数据验证，页面中不植入假圣地。
